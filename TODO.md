# OpenSheet execution backlog

Updated **2026-10-22**. See [ROADMAP](ROADMAP.md) for stage gates and [research](docs/competitive-research.md) for rationale. Baseline is 0.1.1 / `fb76c4e`.

## How to use this backlog

All unchecked items are **planned**, not implemented or verified by this document. Existing capabilities are starting points, not tasks to rebuild. Assign a named owner and reviewer when moving an item to active work; the roles below are responsibility suggestions, not staffed assignments.

- **P0:** blocks trust, acceptance evidence or safe release. **P1:** required for the planned v1 scope. **P2:** post-v1/conditional, unless discovery explicitly promotes it.
- **S:** about 1–3 engineer-days; **M:** 4–8; **L:** 9–15; **XL:** decompose after an RFC/spike. Estimates exclude external feedback delays and are provisional. Split L/XL items into reviewable issues before implementation.
- Metadata format: priority / milestone / effort / owner role / dependencies. `none` means no backlog prerequisite, not no technical work.
- Completion requires a PR/commit, the named acceptance artifact, applicable tests, documentation and review of failure paths. Never check an item solely because code exists.
- Required v1 set: all P0/P1 items below. P2 items require the M5 entry decision. M0 documentation/discovery may overlap M1 diagnostics; a release gate cannot be bypassed by overlap.
- A blocked item records the concrete blocker and next evidence needed. Review active work weekly, milestone scope every two weeks, roadmap monthly.
