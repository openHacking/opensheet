The registry observation was produced with `node scripts/audit-npm-versions.mjs benchmarks/NEW-REPORT.json`; it queries the public npm registry for every current package manifest and records the source revision, dirty-tree flag, Node version and returned version lists. The recorded run had unrelated staged diagnostic files and the audit script itself in the worktree; package manifests were not changed. Re-run rather than assume the observation remains current. A failed lookup or unexpected publication state makes the command fail and is retained in its output.

The automated [consistency checks](../tests/documentation-consistency.test.ts) cover package candidate labels, agent navigation file entries, formula counts, the unversioned-head exception and a limited set of Markdown file links. They do not parse all Markdown, check anchors, resolve reference usages or verify external sites. The [release review checklist](capabilities.md) remains necessary as the repository evolves.

Adversarial review considered four likely failure modes: confusing the installed preview with the candidate, treating a pure Node import as a browser workbook, presenting a historical benchmark as a current release result, and advertising internal rule prototypes as persisted features. The package/registry comparison, runtime and reader sources, dated performance evidence, and explicit prototype rows address those specific risks. They do not close independent browser, accessibility, interoperability, performance, adoption or release gates in the backlog.
