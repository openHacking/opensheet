# Formula semantics and verification

Unreleased 0.2.0-dev.0 development candidate. The [generated function reference](formula-functions.md) derives names, argument counts, signatures and evaluation strategy from the same immutable registry used by pure and Worker-backed evaluation. `functionDefinitions`, `functionDefinition(name)` and `supportedFunctions` are public exports of `@opensheetjs/formula`. Names passed to `functionDefinition` are canonical uppercase names; unknown names return `undefined`.

## Current contract

- Both engines validate function existence and arity before visiting arguments. Unknown functions yield `#NAME?`; invalid argument counts yield `#VALUE!`.
- `IF` evaluates only the selected scalar branch. Omitted false branch returns false. `IFERROR` evaluates its fallback only on an error. Array-valued branches and dynamic arrays are outside the supported profile.
- `COUNT` counts numeric values. Direct booleans and finite decimal numeric text also count; references/ranges count numbers only. Empty strings, nonnumeric text and ordinary error values do not count. Internal `#LIMIT!` and `#CYCLE!` failures propagate through aggregates, including COUNT/COUNTA, so work exhaustion cannot masquerade as a successful count. Numeric text uses decimal/exponent syntax, not locale-specific dates, currency, thousands separators or hexadecimal.
- `COUNTA` counts nonblank values, including empty strings and error values.
- `AND`/`OR` ignore text and blank cells in references/ranges, include numeric zero/nonzero and booleans, and return `#VALUE!` when no usable value remains. They propagate errors even after a decisive logical value; they are not lazy branches. Direct strings TRUE/FALSE are accepted by the existing OpenSheet logical coercion; other direct strings fail. This differs from LibreOffice documentation that rejects all direct text, and needs reader-version fixtures before broader compatibility claims.
- `MIN`/`MAX` include direct boolean values and finite decimal/exponent numeric text; invalid or empty direct text yields `#VALUE!`. Referenced booleans and text are ignored. With no numeric values they return zero. This follows the direct-versus-reference distinction described in Microsoft's [MIN](https://support.microsoft.com/en-us/excel/functions/min-function) and [MAX](https://support.microsoft.com/en-us/excel/functions/max-function) documentation, but the supported text syntax is narrower than locale-dependent spreadsheet parsing. A LibreOfficeDev alpha differs on both direct numeric text and one referenced-boolean case; see [reader evidence](formula-reader-findings.md).
- `SUM` includes direct booleans and finite decimal/exponent numeric text, while ignoring referenced booleans/text; invalid or empty direct text returns `#VALUE!`. The direct/reference distinction is illustrated in Microsoft's [SUM examples](https://support.microsoft.com/en-us/excel/use-the-sum-function-to-sum-numbers-in-a-range); locale-dependent text parsing is outside this profile. `AVERAGE` currently aggregates numeric values only and returns `#DIV/0!` when no numeric values remain; nonnumeric or empty direct text returns `#VALUE!`, while referenced text is ignored. This error distinction is also described in Microsoft's [AVERAGE documentation](https://support.microsoft.com/en-us/excel/functions/average-function). Its direct boolean and numeric-text semantics remain unresolved. Aggregation uses binary64 arithmetic and returns `#NUM!` on nonfinite output; it is not compensated/high-precision summation.
- Scalar functions reject range arguments rather than selecting an arbitrary first element. `ROUND` truncates the digit count toward zero and rounds the shortest round-trippable decimal representation; broad decimal tie/precision compatibility remains unverified.
- Existing dependency depth, reference-work and read-batch limits still apply. Pure evaluation and full Worker evaluation have different work budgets; this corpus tests their common supported profile rather than equating all resource ceilings.
- A cold calculation permits up to 128 nested formula cells; scalar or empty referenced cells do not consume a formula-depth slot. A `#LIMIT!` result is not cached and is not swallowed by `IFERROR`, because it signals incomplete work. Previously computed cached dependencies can reduce the work needed for a later read, so depth exhaustion can depend on cache state; callers must treat `#LIMIT!` as incomplete rather than a stable value.
- `#CYCLE!` is an internal circular-dependency signal: it propagates through `IFERROR` and is not cached. Lazy branches that are not evaluated do not create a cycle. Ordinary errors such as `#DIV/0!` remain catchable. This is the OpenSheet contract, not a claim of parity with every spreadsheet application's circular-reference settings.
- In `CONCAT` and `TEXTJOIN`, an encountered internal `#LIMIT!` or `#CYCLE!` takes precedence over an earlier ordinary error, so `IFERROR` cannot hide incomplete computation. `TEXTJOIN` evaluates delimiter and ignore-empty arguments before its values, subject to the work limit. This does not imply evaluation of branches skipped by lazy functions.
- Binary operators and ordinary scalar functions evaluate their operands from left to right and stop at the first error. The Worker follows the same ordering as pure evaluation. Dependency tracking remains conservative, so a later edit can make previously skipped references relevant and trigger recalculation.
- Numeric literals that overflow binary64, such as `1e309`, are represented as `#NUM!` in the parsed expression; the error propagates when evaluated, can be caught by `IFERROR`, and does not affect an unselected lazy branch. Formula rewrites print the error rather than an unparseable `INFINITY` identifier. Pure-evaluator callbacks returning nonfinite numbers are likewise treated as `#NUM!`. An independent LibreOfficeDev alpha handles these overflowing literals differently; see [reader findings](formula-reader-findings.md).

## Text and boolean function profile

The registry now contains 45 functions, including zero-argument `TRUE()`/`FALSE()` and `LEFT`, `RIGHT`, `MID`, `LEN`, `TRIM`, `UPPER`, `LOWER`, `CONCAT`, `TEXTJOIN`.

- Character positions and lengths count Unicode code points, not UTF-16 units or grapheme clusters. Supplementary emoji count once; combining marks and variation selectors count separately. Legacy Excel compatibility modes may differ.
- Text-producing functions cap output at 32,767 UTF-16 code units and return `#VALUE!` above that limit. `LEN` can inspect longer input. Range joins stream without retaining an item array, including empty ranges; work budgets still apply.
- Text conversion uses empty text for blanks, uppercase TRUE/FALSE for booleans, and unformatted numeric strings. `TEXTJOIN` ignores blank/empty strings when requested, but preserves zero and false. Delimiter and ignore-empty arguments are scalar; delimiter arrays are unsupported.
- Binary `&` uses the same text conversion and a 32,767 UTF-16-unit output limit. Comparisons are case-insensitive for text and order different types as numbers, then text, then booleans; blank references compare as zero. This is OpenSheet's declared profile, not a claim of reader parity.
- `TRIM` collapses ASCII spaces only, preserving tabs and nonbreaking spaces. Case conversion uses locale-independent JavaScript Unicode casing. This is an explicit profile, not a claim of identical locale behavior across office products.
- XLSX export adds `_xlfn.` to CONCAT/TEXTJOIN function tokens while preserving quoted strings and sheet names. Import evaluation accepts `_xlfn.` and `_xlfn._xlws.` prefixes; unknown functions still yield `#NAME?`.

Boundary tests cover output overflow, Unicode, empty ranges, error fallback, Worker edits/undo and independently recalculated XLSX imports after cache expiry/reopen. The 81-case reader run and its remaining differences are recorded in [reader findings](formula-reader-findings.md).

## Rounding and conditional profile

`ROUNDUP`, `ROUNDDOWN`, `INT`, `MOD`, `IFNA` and `IFS` are implemented. Directed rounding truncates the digits argument toward zero, then quantizes the input's shortest round-trippable decimal representation using bounded integer arithmetic. This avoids binary scaling artifacts such as ROUNDUP(1.1,2) becoming 1.11. Very large positive digit counts preserve the input; unrepresentable nonzero results yield `#NUM!`. Zero results normalize negative zero. `ROUND` uses the same digit truncation with nearest rounding and halfway ties away from zero.

`MOD` uses the same shortest-decimal input policy and exact integer remainder arithmetic before converting the result back to binary64; its sign follows the divisor. A zero divisor returns `#DIV/0!`. This gives MOD(0.3,0.1)=0 without intermediate binary remainder artifacts. This policy is explicit and does not assert bitwise agreement with every Excel precision mode. `INT` floors toward negative infinity.

`IFNA` evaluates its fallback only for `#N/A`; other errors propagate. `IFS` requires complete test/value pairs (up to 127), checks arity before reading cells and evaluates pairs in order until the first true test. Unselected values and later tests are not read. No match returns `#N/A`. Scalar-only inputs and existing logical coercion apply. Lazy IFS is an OpenSheet profile that must be compared with each target reader; no eager/dynamic-array compatibility claim is made. XLSX future-function encoding also covers IFNA/IFS.

Sources consulted on 2026-10-23: [ROUNDUP](https://support.microsoft.com/en-us/excel/functions/roundup-function), [ROUNDDOWN](https://support.microsoft.com/en-us/excel/functions/rounddown-function), [MOD](https://support.microsoft.com/en-us/excel/functions/mod-function), [IFNA](https://support.microsoft.com/en-us/excel/functions/ifna-function), and [IFS](https://support.microsoft.com/en-us/excel/functions/ifs-function). The formula corpus includes their basic examples and separate explicit profile/boundary cases. Tests additionally cover subnormal/extreme exponents, signed integer remainder identities, and pure/Worker branch read isolation.

## Date profile

`DATE`, `YEAR`, `MONTH`, `DAY` and `DAYS` use the workbook's persisted `dateSystem` in both Worker and export/snapshot evaluation. Standalone callers can pass the optional fourth argument to `evaluateFormula(ast, read, maxCells, dateSystem)`; its default is `'1900'`. The public `DateSystem` type is `'1900' | '1904'`. Computation uses UTC calendar operations, with no dependence on the machine's time zone or daylight saving transitions.

- In 1900 mode, serial 1 is 1900-01-01 and 60 is the compatibility date 1900-02-29. Component functions treat serial 0 as year 1900, month 1, day 0. In 1904 mode, serial 0 is 1904-01-01 and there is no fictional leap day.
- Supported serials are nonnegative and before the day after 9999-12-31 (maximum whole-day serial 2958465 or 2957003 respectively). Out-of-range values return `#NUM!`. Component functions discard the time fraction; DAYS subtracts numeric serials including fractions.
- DATE truncates numeric arguments, offsets year 0–1899 by 1900, rejects years outside 0–9999, and normalizes month/day overflow along the selected serial calendar. An unrepresentable intermediate UTC month or out-of-range result returns `#NUM!`.
- Date text supports exact `YYYY-MM-DD`, validates the real calendar (plus 1900-02-29 in 1900 mode), and does not guess locale-specific forms. Invalid date text returns `#VALUE!`. Numeric text uses the existing numeric coercion. Locale date/time strings, alternative calendars, negative serials and volatile TODAY/NOW are outside this profile.

Sources: Microsoft [DATE](https://support.microsoft.com/en-us/excel/functions/date-function), [DAYS](https://support.microsoft.com/en-us/excel/functions/days-function), and [YEAR](https://support.microsoft.com/en-us/excel/functions/year-function), consulted 2026-10-23. Independent reader results are recorded separately; implementation of this profile does not establish complete Excel compatibility.

## Conditional aggregate profile

SUMIF/SUMIFS, COUNTIF/COUNTIFS and AVERAGEIF/AVERAGEIFS share a streaming execution plan across pure and Worker evaluation. Criteria are compiled once. Multi-criteria ranges must have equal row and column counts and complete pairs (up to 127); invalid shapes fail before reading cells. Single-criterion SUMIF/AVERAGEIF project the optional value range from its top-left over the criteria range's dimensions, including when only one value-cell reference is supplied. Worker dependencies include this projected range so changes outside the literal reference still invalidate results.

- Criteria support `=`, `<>`, `<`, `>`, `<=`, `>=`, case-insensitive text, decimal numeric text, booleans, and `*`/`?` wildcards with `~` escaping. Question marks match one Unicode code point. Text ordering uses locale-independent lowercase UTF-16 lexicographic ordering; locale collation and date-text criteria are not inferred.
- Numeric criteria compare numeric cells and decimal numeric text; blank cells compare as zero. Empty-text criteria match blanks and empty strings. Boolean criteria compare logical values without coercing them to numbers. Wildcards match text cells, including empty strings where the pattern permits, rather than numeric/boolean cells.
- Ordinary errors in a criteria range do not match ordinary criteria; exact error-code text can match them. Matching value-cell errors propagate. Internal cycle/work-limit errors propagate. Numeric sums/averages ignore referenced text, logical values and blanks. No match returns zero for SUM/COUNT and DIV/0 for AVERAGE. Results use binary64 arithmetic and nonfinite output yields NUM.
- Criteria length is limited to 32,767 UTF-16 units. Conditional aggregates and lookups within one formula expression share a one-million-unit text budget: criterion and compared string lengths are charged in UTF-16 units, including wildcard compilation and normalization, and wildcard traversal consumes additional steps. Exhaustion returns `#LIMIT!`, including for nested calls and non-wildcard comparisons over enough long strings; this is a resource limit, not an Excel compatibility rule. Separately evaluated referenced cells have their own budget, so this is not a total workbook CPU bound. The matcher does not compile user text into a regular expression. Existing evaluator reference-work limits also apply. Range values are not materialized into an array.

This is the explicit supported coercion/error profile; per-reader differences remain tracked. Tests cover mixed inputs, no match, escaped wildcards, invalid shapes, bounded work, projected dependency edits, undo/redo, row insertion and persistence reopen. Microsoft [SUMIF](https://support.microsoft.com/en-us/excel/functions/sumif-function) and [AVERAGEIFS](https://support.microsoft.com/en-us/excel/functions/averageifs-function) were consulted on 2026-10-23; their broader reader-specific coercion details are not assumed identical to this profile.

## Lookup profile

INDEX, MATCH, VLOOKUP and XLOOKUP share a streaming lookup runner in pure and Worker evaluation. The explicit supported modes are:

| Function | Supported                                                                                                                          | Explicitly unsupported                                              |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| INDEX    | Scalar positive row/column indices; one-row two-argument form indexes columns; indices truncate toward zero                        | Zero-index array/reference results, multiple areas, computed arrays |
| MATCH    | Match type 0 exact/wildcard; 1 or omitted ascending nearest; -1 descending nearest, in a row or column vector                      | Mixed-type or unsorted approximate vectors, matrix inputs           |
| VLOOKUP  | FALSE/0 exact/wildcard; TRUE or omitted ascending nearest in the first column; scalar result column                                | Mixed-type or unsorted approximate keys                             |
| XLOOKUP  | Scalar vector result, exact/nearest/wildcard linear search and exact/nearest binary search on sorted keys; lazy not-found fallback | Binary wildcard search, matrix/array results, computed arrays       |

Unsupported modes return `#VALUE!` instead of silently changing their meaning. Out-of-range INDEX/VLOOKUP result coordinates return `#REF!`; no match returns `#N/A` unless XLOOKUP has a fallback. Return vectors must have the same shape as lookup vectors. Only the selected result cell is read. Ordered MATCH/VLOOKUP scans and verifies the entire key vector, returning the last duplicate candidate; unsorted or mixed-type keys return `#VALUE!`. XLOOKUP nearest-mode ties retain the first candidate in the selected direction and do not require sorted data. All scans remain subject to the formula work budget.

Matching is case-insensitive and type-sensitive: number 7 and text "7" remain distinct. Blanks compare as numeric zero; empty text remains text. Blank result cells return zero. Approximate comparisons use values of the same type and locale-independent lowercase UTF-16 text ordering. Encountered lookup-cell errors propagate; unvisited later cells and an unused fallback are not evaluated. Text comparisons and wildcard matching consume the per-expression budget shared with conditional aggregates; exhaustion returns `#LIMIT!`, including in binary lookup. Patterns are limited to 32,767 units. XLOOKUP exact mode treats wildcard characters literally. Reference-work budgets also apply.

XLOOKUP search modes 2 and -2 perform binary search on keys supplied in ascending or descending order respectively. They do not scan to verify order; unsorted keys can produce incorrect results. Keys sampled during the search must be comparable with the lookup value. For an exact match among equal keys this implementation selects the first index in the provided vector; for an approximate match it selects the duplicate at the insertion boundary. A LibreOffice development build differs on a descending exact-duplicate case; Excel behavior remains unverified. Wildcard match mode 2 cannot be combined with binary search.

Sources consulted 2026-10-23: Microsoft [MATCH](https://support.microsoft.com/en-us/excel/functions/match-function), [VLOOKUP](https://support.microsoft.com/en-us/excel/functions/vlookup-function), and [XLOOKUP](https://support.microsoft.com/en-us/excel/functions/xlookup-function). Supported-mode tests do not assert compatibility for excluded modes or all reader-specific coercion rules.

## Evidence and provenance

`tests/fixtures/formula-corpus.ts` contains hand-authored inputs and expected results, independent of either evaluator. `tests/formula-corpus.test.ts` runs every fixture through the pure engine and through actual worker dispatch with IndexedDB test storage, including zero cache and close/reopen. `tests/e2e/formula.spec.ts` also runs the corpus in real Chromium/WebKit/Firefox Workers and reopens persisted data. Every registered function must have a fixture. Unknown-function tests verify that argument ranges are not read. Existing storage tests cover reference transforms, transitive invalidation, cycles and structural/history behavior.

Expected-result tags distinguish simple independently calculated arithmetic, documented rules and explicit OpenSheet limits. Sources consulted on 2026-10-22:

- [Microsoft COUNT](https://support.microsoft.com/en-us/excel/functions/count-function): distinguishes direct boolean/numeric text arguments from referenced values and ignores errors for counting.
- [Microsoft AND](https://support.microsoft.com/en-us/excel/functions/and-function) and [OR](https://support.microsoft.com/en-us/excel/functions/or-function): referenced text/empty cells are ignored; an entirely ignored range produces an error.
- [LibreOffice logical functions](https://help.libreoffice.org/latest/en-GB/text/scalc/01/04060105.html): documents zero/nonzero, ignored referenced text/blanks, empty logical inputs and error propagation.
- [Microsoft MAX](https://support.microsoft.com/en-gb/excel/functions/max-function): direct numeric text/logical arguments are included, demonstrating a remaining OpenSheet coercion gap.

The initial corpus was documentation-backed. A subsequent real LibreOfficeDev 26.8.0.0.alpha0 run is recorded in `benchmarks/formula-reader-2026-10-23.json`, with source and recalculated XLSX artifacts and hashes; 36 of the initial 46 expectations agreed. See [reader findings](formula-reader-findings.md). No Excel execution is claimed. Microsoft AVERAGE documentation states that directly typed logical/numeric text arguments are not counted; independent versioned reader results are still needed to settle broader coercion behavior. Versioned Excel and stable LibreOffice confirmation, precision/date-system coverage and the full CALC-01 acceptance gate remain outstanding.

## Compatibility change

The previous `COUNT(1,"x",TRUE)` fixture expected 1; it now returns 2 under the documented direct-argument rule. Referenced logical/text cells remain excluded. `AND/OR` now ignore referenced blanks/text and report all-ignored/error cases consistently. Scalar range inputs that previously selected the first item in the pure evaluator now yield `#VALUE!`, matching the Worker. Regenerate external caches/recalculate after upgrade; no persisted cell inputs are rewritten.
