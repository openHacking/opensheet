# Initial acceptance workload profile

DISC-01 provisional profile, 2026-10-22. No independent-user validation is claimed. Preserve the roadmap thresholds until an explicit scope ADR changes them.

## Task scripts

1. **Order worksheet:** create two sheets, enter text product IDs (including leading zeros), quantities, decimal prices and booleans; calculate line totals and SUM; edit, undo/redo, filter and sort; download native JSON/binary, reopen and compare every input, formula result, style, merge and sheet identity. XLSX export must show known losses before download. Validation joins this script when implemented; existing multi-key sort remains subject to its own acceptance gate.
2. **Budget model:** use Budget Simulator; change D2 to 3, verify F2 = 7200, undo to D2 = 1, redo; enter cross-sheet and mixed absolute references; repeat after eviction and reopen. Formula errors and stale revisions must be actionable. Expand to named ranges and the agreed formula corpus without replacing baseline assertions.
3. **Local file review:** import a synthetic XLSX with strings, blanks, numbers, booleans, dates, formula-without-cache, merges and two sheets; inspect report; edit and export; independently open/recalculate/save in Excel and LibreOffice; reimport and compare documented supported assertions. Keep original input. A parse error, quota failure or cancelled import must leave the previous revision intact.

Existing automated anchors: `tests/e2e/playground.spec.ts`, `tests/e2e/scenes.spec.ts`, `tests/interop.test.ts`, `tests/storage.test.ts`. These are starting evidence, not completion of each future workflow.

### Reproducible inputs and observations

- **Order:** start with an empty workbook and sheets `Orders` and `Summary`. On `Orders`, enter headers `ID`, `Quantity`, `Price`, `Active`, `Total` in A1:E1. Enter `0001`, 3, 12.5, true in A2:D2; `0002`, 2, 7.25, false in A3:D3; and `0003`, 1, 100, true in A4:D4. IDs are literal text. Set E2:E4 to `=B2*C2`, `=B3*C3`, `=B4*C4`; set `Summary!A1` to `=SUM(Orders!E2:E4)`. Expected line totals are 37.5, 14.5 and 100; the summary is 152. Change B2 to 4: E2 is 50 and summary is 164.5; undo restores 152 and redo restores 164.5. Filter `Active` to true: IDs `0001` and `0003` remain visible; other blank worksheet rows are also filtered out. Clear the filter and sort A2:E4 by ID descending: order is `0003`, `0002`, `0001`, and the summary remains 164.5. Apply a numeric format to C2:C4 and merge G1:H1 with the text `Orders`; verify these and sheet IDs after reopening both native formats. Keep the unmodified export and compare formulas and typed inputs as well as calculated results. This is a literal fixture, not a random seed. The [three-browser Worker test](../tests/e2e/order-workload.spec.ts) automates the core edit, filter, sort, import and reopen checks; it does not establish native input, file-loss UI or independent-reader acceptance.
- **Budget:** use the checked-in [budget fixture](../apps/playground/src/budget-fixture.ts), reset the scene before each run, and retain the fixture revision/hash with the result. Initially the UI's planned spend is $13,097; after D2 changes from 1 to 2 it is $15,497, and undo returns $13,097 ([browser assertion](../tests/e2e/scenes.spec.ts)). Separately, setting D2 to 3 must yield F2 = 7,200. The [budget Worker test](../tests/e2e/budget-workload.spec.ts) pins the fixture source hash and sets `Notes!D2` to `='Launch budget'!$D2*'Launch budget'!E$2` and `Notes!E2` to `='Launch budget'!$D$2+'Launch budget'!E$2`. At D2 = 1 these yield 2,400 and 2,401; at D2 = 3 they yield 7,200 and 2,403, while F11 changes from 13,097 to 17,897. Three browser engines check undo, redo and reopen with page caching disabled. This does not prove cache eviction, native input or the entire task.
- **File review:** use the CC0 hand-authored [basic FODS](../tests/fixtures/interop/basic.fods), the [manifest](../tests/fixtures/interop/manifest.json) and its linked LibreOffice-authored XLSX. The manifest specifies expected values, losses and known reader differences, including the boolean `TYPE` difference. Preserve original files and report import/export issues; do not turn those known differences into passes. The existing corpus does not yet cover every feature in the task script or provide Excel and visual acceptance.
- **Scale:** use 100 columns and the fixed `LCG-1664525-1013904223` fixture from `fixtureValue` in `packages/core/src/engine.ts`; the result records the generator identifier and workload parameters. One million cells means 10,000 rows. The generator and [performance protocol](performance.md) define the data and verification; formula and XLSX workloads are separate.

These are baseline inputs, not substitutes for independent-user fixtures. A result must identify the exact source/build, dataset or file hash, operation sequence, observed values, differences and retained artifact. Failure or a missing observation is recorded as such, not omitted from the task report.

## Deterministic dataset families

- Mixed capacity: existing Performance Lab generator and unchanged full-cell checksum/undo/dispersed-edit protocol. Preserve its seed/formula in downloaded result artifacts.
- Dense scalars: rectangular rows of text IDs, positive/negative numbers, zero, false and empty strings.
- Sparse: occupied cells in distant 64 × 32 pages, including dimension edges.
- Strings: repeated and unique long text, Unicode and unpaired surrogate preservation.
- Formulas: cross-sheet chains, fan-out, overlapping ranges, lazy branches and errors.
- Metadata: styles, dimensions, hidden axes, merges, frozen panes and history.

Each new fixture must record dimensions, seed or literal inputs, independently specified expected values and intended failure boundary. Large fixtures must be generated rather than committed as opaque binary blobs without provenance.

## Reference environment and limits

The proposed editor correctness profile is desktop Chromium, Firefox and WebKit with module Workers, IndexedDB, Web Locks and BroadcastChannel. Native Safari and the specific release browser versions still require explicit records; Playwright WebKit is not Safari. Performance requires macOS/Chromium and a mainstream Windows laptop/Chromium, not an assumption of equivalent performance in other browsers. Pure Node utilities are a separate profile described in [Node and headless use](node-usage.md), not an editable Node workbook guarantee.

Available local diagnostic machine: Mac mini Mac16,10, Apple M4 (10 CPU cores), 16 GB memory, arm64, AC power. Browser build, OS version, command, tree revision and concurrent workload belong in each result. This machine alone does not satisfy the Windows reference-machine gate; the Windows hardware and browser version are not yet selected and no Windows results are available. Native screen-reader/IME trials require their own OS/browser/input-method records.

The current formula subset and mode restrictions are listed in [formula semantics](formulas.md); the [adapter documentation](../packages/adapter-sheetjs/README.md) and [fixture manifest](../tests/fixtures/interop/manifest.json) describe mappings and reported losses. These are current implementation boundaries, not a frozen, independently validated v1 profile.

Required strict capacity gate: 1,000,000 mixed populated cells, three rounds, edit P95 ≤100 ms, complete scroll-frame P95 ≤33 ms, restore ≤10 s, complete data verification and dispersed undo/redo. 10m remains a conditional stretch target. Run capacity benchmarks sequentially with other test/build workloads stopped.

The target behavior for a resource-limit rejection is an explicit error and no partial publication of a mutation; verify it at the particular operation and boundary, rather than assuming every failure path is covered. Default storage budget is 256 MiB; ordinary traversal and undo/working-set budgets are 32 MiB each; a read batch is at most 16,384 cells. XLSX conversion remains materialized. Quota/permission checks at initialization cannot promise future space or protection from browser origin eviction. Native backups must be downloaded separately.

## Evidence outside this environment

Five developer interviews, three independent integrations, Windows hardware, Excel and complete stable LibreOffice reader acceptance, real native IME and screen-reader trials, two release-capable maintainers and the RC observation period remain open. Record actual participants and consent; do not invent results or designate maintainers without availability.
