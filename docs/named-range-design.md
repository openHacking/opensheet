# Named-range integration boundary

Status: internal rectangle-only model; names are not accepted by the formula parser, commands, public API, native files or persisted engine. CALC-05 and its COR-02 dependency remain open. No new public schema version is assigned by this prototype.

The prototype identifies a name and its optional worksheet scope with stable IDs. Its target is either a half-open rectangle on a stable sheet ID or a broken target. ASCII names are case-insensitive within a scope; a sheet-local name shadows a workbook name of the same spelling, even if the local target is broken. Duplicate IDs and duplicate names within one scope are rejected. Names that conflict with the current parser's A1 tokenization, booleans, or the reserved single letters `R` and `C` are rejected. This is a deliberately narrow provisional syntax, not an Excel compatibility claim.

An axis insertion at or before a target shifts it, an insertion inside expands it, and an insertion at its end leaves it unchanged. Deletion shrinks the covered membership; removing every member leaves a broken target rather than silently rebinding the name. Removing a worksheet removes names scoped to that sheet and breaks surviving names whose target was on it. A sheet rename does not alter targets because they use IDs. Unit tests compare 2,000 seeded transformations with an independent membership model; Chromium, Firefox and WebKit Workers exercise 8,192 definitions and lookup/transform isolation. These tests do not exercise persisted workbooks or formulas.

The model limits a collection to 8,192 names and one million UTF-16 units of name text. The original validation and transformation are synchronous. Reusing the rectangle schema reduced local Node timings substantially; the measurements and their limits are in [performance](performance.md). Internal staged variants check cancellation and yield between groups of entries; they return a detached result only after full validation. Their caller must keep the input and sheet metadata stable until the operation settles. They do not themselves acquire a revision, enforce immutability or publish changes. These prototypes are not yet suitable for an interactive publication path without integration and end-to-end measurement. Limits are provisional, not established product budgets.

Before exposure, the implementation must resolve formula syntax and scalar/range behavior, qualified scope lookup and shadowing, name rename/delete semantics, dependency tracking and cycles, copy/sort/structural edits, sheet operations and error propagation. Formula-defined names, Unicode names, external references and multi-area ranges are not represented by this model. Explicit native file and engine versioning, verified backup/rollback, staged atomic publication, history, import/export reporting and old-reader rejection must precede persistence. UI, accessibility, independently authored Excel/LibreOffice fixtures, failure injection, memory and cross-device acceptance remain required.
