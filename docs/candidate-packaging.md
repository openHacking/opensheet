# Candidate packaging rehearsal

`0.2.0-dev.0` is an unreleased development candidate. These instructions create local archives for inspection and consumer testing; they do not publish packages or establish stable-release approval.

Build and verify the workspace first, then create one archive per package in an empty output directory:

```sh
pnpm check
mkdir -p artifacts/candidate
for package in adapter-sheetjs core formats formula opensheet plugin-sdk react renderer testing vue; do
  node scripts/pack-candidate.mjs "$package" "$PWD/artifacts/candidate/$package.tgz"
done
```

The script refuses to overwrite an existing archive. It copies each package to a temporary directory, resolves its `workspace:*` dependencies to the corresponding workspace package versions, then runs `pnpm pack` on that copy. It rejects unsupported workspace specifiers and leaves the source manifests unchanged. Build artifacts must already be current; the script does not build them. The output must still be reviewed before any publication decision.

Run `node scripts/release-pack-acceptance.mjs benchmarks/NEW_REPORT.json` to pack each built package twice, compare archive hashes, compare staged archives against direct `pnpm pack` file lists, file contents and parsed manifests, and install all ten archives into an isolated consumer. It requires `pnpm` and `tar` on the path. It checks required licenses, declarations, Worker and CSS files, imports all entry points without browser globals, exercises core/formula/adapter/format APIs and compiles a TypeScript consumer. The consumer uses `--prefer-offline`, may fetch third-party dependencies and retains a lockfile next to the report.

Direct repeated `pnpm pack` runs were observed to reorder workspace dependency keys in `opensheet`'s packed manifest, producing different archive hashes; the [first failed report](../benchmarks/release-pack-candidate-2026-11-12.json) is retained. Repeated staged rehearsals on the same host produced matching hashes for all packages and passed the checks ([first](../benchmarks/release-pack-staged-candidate-final-2026-11-12.json), [repeat](../benchmarks/release-pack-staged-candidate-repeat-2026-11-12.json), [after rebuilding](../benchmarks/release-pack-post-build-candidate-2026-11-12.json), [validated script](../benchmarks/release-pack-validated-candidate-2026-11-12.json)). Two intervening offline consumer attempts failed because the local pnpm store lacked `@types/react`; the successful runs used `--prefer-offline`. These repetitions do not establish cross-platform reproducibility, signatures, provenance attestation or registry publication. Browser integration and upgrade limitations remain documented in [verification](verification.md) and the [changelog](../CHANGELOG.md).

The [independent-directory build harness](../scripts/clean-build-acceptance.mjs) copies package source without `dist` or `node_modules` into two new temporary workspaces, installs from the frozen lockfile, builds all packages and creates staged archives. The [first local run](../benchmarks/clean-build-candidate-2026-11-12.json) and [final repeat](../benchmarks/clean-build-candidate-final-2026-11-12.json) recorded identical input hashes and all ten output hashes; the repeat also hashes the copied lockfile, root configuration, license and build scripts. Those output hashes matched the separately inspected workspace archives. Both builds used the same machine, Node/pnpm and package store, and the copied source came from a dirty worktree. This is not an independent toolchain, clean-commit or cross-platform build and does not replace signed provenance.

The earlier [attachment-fix archives](../artifacts/opensheet-0.2.0-dev.0-attachment-fix/manifest.json) predate the security dependency updates. The current [manifest](../artifacts/opensheet-0.2.0-dev.0-security-fix/manifest.json) and [checksums](../artifacts/opensheet-0.2.0-dev.0-security-fix/SHA256SUMS) accompany ten installable archives. Their hashes match the two [independent-directory builds](../benchmarks/clean-build-security-fix-2026-11-12.json) and the [inspected consumer archives](../benchmarks/release-pack-security-fix-2026-11-12.json). `scripts/create-candidate-artifacts.mjs` creates a new directory only, packs each package and requires each hash to match both build runs and the consumer report; it removes its newly created directory if verification fails. Verify the files again before use with `shasum -a 256 -c SHA256SUMS` from that directory. The manifest records evidence hashes, not signatures or release approval.

After the development-tool security update, two more [independent-directory builds](../benchmarks/clean-build-toolchain-fix-2026-11-12.json) and the [installed-consumer rehearsal](../benchmarks/release-pack-toolchain-fix-2026-11-12.json) produced the same ten archive hashes as the saved candidate. The candidate manifest predates the toolchain update; these later reports record the updated inputs and are not signed provenance.

After adding the SheetJS tarball integrity to the workspace lockfile, another pair of [independent-directory builds](../benchmarks/clean-build-sheetjs-integrity-2026-11-12.json) and [installed-consumer rehearsal](../benchmarks/release-pack-sheetjs-integrity-2026-11-12.json) produced the same ten candidate archive hashes. These builds share one host, toolchain and package store; they do not independently authenticate the downloaded SheetJS archive.

Subsequent playground recovery changes and the core zero-cache search change postdate those reports. The saved application and package hashes therefore do not describe the current tree. The `.tgz` archives are ignored by Git and remain local build artifacts; the committed manifests and checksums are historical evidence, not self-contained packages. Rebuild and recheck the final application, package archives and release evidence before treating this candidate as a release.

After the search change, a fresh [pack-and-consumer rehearsal](../benchmarks/release-pack-search-final-2026-11-12.json) packed and inspected all ten current packages twice and passed the isolated consumer checks. This is a local dirty-tree rehearsal, not a clean-commit or independent-toolchain build; it does not replace the older candidate archives or constitute publication.

Because these candidate package versions are not published to the registry, installing only `opensheet.tgz` cannot be assumed to resolve its internal dependencies. The [local candidate host](../examples/local-candidate/README.md) shows a pnpm override for each required local archive. Its [updated isolated production-host test](../benchmarks/local-candidate-host-security-fix-2026-11-12.json) verifies archive hashes and lockfile paths, a frozen-lockfile reinstall, editor creation, automated keyboard editing, disposal and reopen in Chromium, Firefox and WebKit under a subpath. It also holds a target's readiness pending, deletes it and verifies that the current workbook stays attached. The example does not establish npm/Yarn, strict CSP, SSR or native-keyboard compatibility.
